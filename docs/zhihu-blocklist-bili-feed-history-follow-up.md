# 知乎黑名单与 B站推荐回退：实现后续记录

> 记录日期：2026-08-27  
> 工作分支：`feature/zhihu-blocklist-bili-feed-history`  
> 当前结论：基础功能已实现，但 B站推荐回退尚未达到可发布质量；本记录用于下一轮继续修复，不代表验收通过。

## 已确认的基础能力

- B站首页可以显示推荐历史导航按钮。
- 点击原生「换一换」后，可以在已记录批次间回退和前进。
- 当前标签页内的批次状态能够工作。

以上只证明基础链路成立，不代表视觉、交互和卡片信息完整性达标。

## 必须修复的问题

### 1. 按钮视觉质量不合格

- 当前按钮整体观感粗糙，与 B站原生「换一换」及 ECHO 既有设计风格不协调。
- 按钮的深浅颜色、启用态、禁用态和可点击状态之间缺少清晰、稳定的视觉层级。
- 当前实现虽然能够看见，但不能作为最终设计发布。

下一轮需要重新设计按钮形态、位置、间距、图标、悬停态、按下态、禁用态及深浅主题表现，并在真实 B站首页截图验收后才能定稿。

### 2. 导航交互不方便

- 当前上一批/下一批的操作方式和按钮布局不够顺手。
- 用户需要花额外注意力理解按钮状态和当前所处批次。
- 批次边界、当前最新批次和历史查看状态缺少明确反馈。

下一轮应先重新确认交互模型，再调整代码。至少需要明确：

- 上一批、下一批与原生「换一换」三者的最终空间关系。
- 当前处于历史批次还是最新批次时的状态提示。
- 到达最早/最新边界时的禁用反馈。
- 用户查看历史时再次点击原生「换一换」的行为。

### 3. 历史卡片统计信息丢失

这是当前最严重的功能缺陷。

复现步骤：

1. 在 B站首页开启推荐回退。
2. 点击原生「换一换」记录至少两个批次。
3. 使用上一批或下一批切换到 ECHO 渲染的历史批次。
4. 检查卡片上的播放数、弹幕数等统计信息。

实际结果：切换到历史批次后，播放数、弹幕数等原卡片信息丢失。

期望结果：历史卡片至少完整保留并显示以下结构化字段：

- 标题
- 封面
- 目标链接
- 作者
- 时长
- 播放数
- 弹幕数

下一轮需要先核对当前 B站卡片 DOM 中各统计字段的真实结构，再检查提取、存储和历史渲染三个阶段分别在哪里丢失数据。不得通过复制整段站点 HTML 绕过结构化数据方案。

## 下一轮处理顺序

1. 只读检查当前 B站普通视频、广告、番剧及其他卡片的统计字段 DOM。
2. 修复结构化提取与数据模型，先保证播放数、弹幕数完整。
3. 修复历史卡片渲染，并用前后批次截图逐卡对照。
4. 重新讨论并确定导航交互与视觉方案。
5. 在登录态连续执行至少 20 次换批，检查信息完整性、边界状态和混批。

## 发布门槛

以下条件全部满足前，不得将 B站推荐回退标记为完成或可发布：

- 历史卡片的标题、封面、链接、作者、时长、播放数和弹幕数均能稳定显示。
- 上一批/下一批操作直观，边界和当前状态清晰。
- 按钮在常见桌面宽度、页面缩放和深浅主题下均符合最终设计。
- 返回最新批次后，B站原生卡片、交互和统计显示完全恢复。
- 连续换批测试不存在半批、混批、重复记录或历史层残留。
