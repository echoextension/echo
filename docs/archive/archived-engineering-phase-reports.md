### 3.2 生产变更

| 区域 | 已验证问题 | 修复 |
| --- | --- | --- |
| Background 标签关闭 | `lastActiveTabId` 会把已非活动的历史标签误判为刚关闭的活动标签 | 使用异步标签存在性分类，将历史活动 ID 只关联到关闭触发的激活转换 |

| 老板键 | Worker 重启后内存状态丢失，无法恢复窗口 | 将事务状态写入 `storage.session`，恢复成功后清理 |
| 快速存图 | 固定 DNR ID 会被并发请求互相覆盖和删除 | 使用串行分配的独立规则 ID、精确 URL 正则、启动残留清理和逐请求释放 |
| NTP 收藏 | sync 失败后 local 降级副本无读取路径 | 使用版本化 local 降级记录，启动恢复并在 sync 成功后清理 |
| Search Box | 隐藏后缩放轮询和光谱 RAF 继续运行 | 显示时启动、隐藏时停止，设置变更不在隐藏状态重启 |
| NTP 初始化 | 壁纸数据请求阻塞搜索、热搜、缩放和输入绑定 | 基础交互立即初始化，收藏栏和壁纸在独立异步流程加载 |
| NTP 搜索建议 | 旧查询响应可以覆盖新查询 | 响应应用前核对当前输入，过时响应直接丢弃且不隐藏新结果 |
| NTP 壁纸缓存 | 404 HTML 等错误 Blob 会进入图片缓存 | 缓存前验证 HTTP、Content-Type 和非空 Blob |
| Options 备份 | 已知设置类型错误会写入任意值并留下部分恢复 | 增加 schema、白名单、类型校验、预验证和触及键回滚 |

### 3.3 红灯到绿灯证据

每个问题均先建立失败用例：

- 非活动历史标签关闭：期望保持标签 3，修复前实际切到标签 1；
- 跨窗口关闭：期望窗口 B 保持标签 11，修复前实际切到标签 9；
- 老板键重启：期望恢复 `normal`，修复前仍为 `minimized`；
- DNR 并发：期望两个并发规则，修复前仅剩固定 ID 的一个规则；
- 收藏降级：期望恢复 local 收藏，修复前得到空数组；
- 搜索框隐藏：期望 interval 和 RAF 停止，修复前 interval 仍存在；
- NTP 启动：期望壁纸请求未完成时表单已拦截，修复前未绑定；
- 搜索建议乱序：期望 `new suggestion`，修复前显示 `old suggestion`；
- 壁纸错误缓存：期望不调用缓存，修复前缓存了 `text/html` Blob；
- 损坏备份：期望零部分写入，修复前写入了字符串设置和新增收藏。

所有失败均由当前代码在本地确定性测试中复现，随后用最小生产修改修复。

## 阶段 5：拆分后台 Service Worker

### 5.1 状态

完成。

### 5.2 生产结构

原单体 `background.js` 已收敛为 43 行薄入口，只负责：

1. `importScripts` 加载；
2. 创建领域服务；
3. 注入依赖；
4. 注册监听器。

新增领域模块：

| 模块 | 状态所有权/职责 |
| --- | --- |
| `settings-service.js` | 安装初始化、旧设置迁移、FRE、设置读取 |
| `command-service.js` | 老板键持久事务、全局静音命令 |
| `tab-coordinator.js` | 标签插入、事件缓存、关闭状态机、切换、开页和搜索 |
| `message-router.js` | 唯一 runtime 消息监听器、协议校验、异步响应和服务分发 |
| `image-service.js` | 图片 Referer 规则、获取、文件名和下载 |
| `network-service.js` | 白名单 JSON 代理和 Bing 建议 |
| `bili-session-service.js` | 按标签 session、sender 校验、关闭清理和补注入 |
| `zhihu-sync-service.js` | 知乎窗口、Port、任务、取消、完成和 Worker 重启恢复 |

### 5.3 事件所有权

- 标签创建、激活、移动、分离、附加和关闭统一由 `tab-coordinator` 注册；
- 原先两套 `onCreated/onActivated/onMoved` 监听器已合并；
- runtime message 只有 `message-router` 一个入口；
- command 由 `command-service` 独占；
- B站设置变化由 `bili-session-service` 独占；
- 知乎 options Port 由 `zhihu-sync-service` 独占；
- 窗口关闭由标签协调器和知乎任务服务分别处理各自明确状态，不共享可变状态。

### 5.4 状态与生命周期改善

- 标签插入和关闭状态都封装在同一协调器实例；
- 所有标签状态按 `windowId` 隔离；
