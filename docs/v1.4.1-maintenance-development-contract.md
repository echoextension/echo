# v1.4.1 行为保持型优化与缺陷修复开发契约

> 制定日期：2026-09-03
> 适用分支：`feature/zhihu-blocklist-bili-feed-history`
> 目标版本：`1.4.1`
> 文档性质：本轮代码修改、代码审查、自动检查和人工验收的约束性契约
> 当前状态：代码实施与自动自检已完成，等待人工冒烟验收

## 1. 契约目的

本轮是在 `1.4.0` 候选基线上进行的维护版本开发，只允许完成以下两类工作：

1. 修复能够由当前代码、失败路径或针对性测试证实的缺陷与回归；
2. 在行为测试保护下继续拆分职责过多的单体文件，提高可维护性和可审查性。

本轮不是功能版本。核心原则是：

> **正常使用路径、界面、交互、文案、默认值和数据含义保持不变；只有已经存在的边界故障消失。**

审计中提出但尚未证实的问题只能作为调查线索。不能因为“理论上可能”就改变产品行为、增加兜底功能或扩大支持范围。

## 2. 冻结的产品基线

### 2.1 明确禁止新增

本轮不得新增或扩展：

- 用户可见功能、按钮、开关、菜单、页面、引导步骤或快捷键；
- 设置项、默认值、权限、host 权限、外部请求目标或数据采集范围；
- B站、知乎、NTP、搜索框或通用输入增强的适用网站、适用页面或能力范围；
- 新的用户文案、营销表述、通知、确认步骤或产品承诺；
- 新的存储数据类别、跨设备同步内容或备份内容；
- 新的远程服务、遥测、日志上传或第三方依赖；
- 审计之外顺手发现但尚未完成证据闭环的产品调整。

### 2.2 必须保持兼容

下列既有契约必须保持：

- `manifest.json` 权限、内容脚本匹配范围和公开页面入口不变；
- 现有设置键、默认值、存储区域和合法取值不变；
- 现有消息 action、Port 名称和消息结果语义保持兼容；
- NTP 壁纸设置、收藏、浏览记录、自定义壁纸和缓存继续兼容现有数据；
- 知乎黑名单继续只保存在当前设备，不进入 sync 或备份；
- B站推荐历史继续按标签页会话隔离，最多保留 10 批，关闭功能或标签页后清理；
- FRE 演示行为不受用户开关影响，正式页面继续服从用户开关；
- 正常网络、正常存储和普通单次操作下的视觉结果及操作顺序不变；
- 中文、英文本地化键集合不因本轮维护发生变化。

### 2.3 允许的版本记录变化

仅允许将维护版本记录更新为 `1.4.1`，并记录实际完成的修复与重构：

- `manifest.json`；
- `package.json` 与锁文件中的根包版本；
- `options/options.html` 中的设置页版本徽标；
- `website/index.html` 中的官网版本结构化数据与下载入口版本标识；
- `CHANGELOG.md`；
- 与本轮直接相关的架构、QA、发布或开发契约文档。

## 3. 缺陷证据门槛

每个缺陷在修改生产代码前，至少满足以下一种条件：

1. 存在能够稳定失败的自动化测试；
2. 控制流能够完整证明错误状态，且测试能够注入对应失败或乱序条件；
3. 浏览器平台规范明确保证相关生命周期或事件语义，当前代码违反该语义；
4. 已有人工复现记录能够唯一定位到当前代码路径。

若测试或进一步阅读否定原假设：

- 不修改生产代码；
- 在本契约完成记录中标为“未证实，不实施”；
- 不以预防性设计为理由扩大修改。

每个修复必须同时具备：

- 修复前能够失败的针对性测试或等价证据；
- 修复后的正常路径断言；
- 对应边界路径断言；
- 不改变公开行为的审查说明。

## 4. 本轮允许调查和修复的问题

### 4.1 知乎同步生命周期

允许调查并在证实后修复：

- 设置页 Port 在 Manifest V3 Service Worker 空闲终止后的断线恢复；
- 同步任务首次写入 session 状态失败后遗留内存任务；
- Worker 握手超时后旧 Port 未主动释放；
- 同步最终提交期间收到取消时的状态一致性。

边界要求：

- 不用定时心跳强行保活 Service Worker；
- 只在断线后按需重连，不产生持续后台活动；
- 不改变授权、首次同步、手动同步、取消、完整快照提交和旧快照保留语义；
- 不扩大知乎支持页面或作者识别规则。

### 4.2 NTP 初始化、持久化和缓存一致性

允许调查并在证实后修复：

- 浏览足迹写入异常中断壁纸渲染提交的回归；
- 一次设置读取失败使壁纸控制器永久无法继续初始化的回归；
- 收藏删除成功、每日模式保存失败时的跨存储部分提交；
- 壁纸开关或空白模式保存失败后的 DOM、内存与 localStorage 镜像不一致；
- 收藏及其更新时间分键同步时的乱序事件；
- 远程壁纸数据在校验前进入长时缓存，以及后台刷新覆盖时序；
- 热搜短响应在数量校验前进入缓存并阻止后续刷新。

边界要求：

- 不改变壁纸选择算法、每日/收藏/锁定三态语义、缓存时长或远程地址；
- 不删除已有收藏、自定义壁纸或浏览记录；
- 不新增提示、重试按钮或设置项；
- 正常存储成功时的写入结果与当前行为一致；
- 失败回滚不得覆盖与本次操作无关的并发状态。

### 4.3 B站页面生命周期

允许调查并在证实后修复：

- 视频工具在脚本初始读取为关闭后，当前文档内无法响应后续开启；
- 推荐历史的晚到恢复结果越过关闭清理；
- 已承诺的同标签页进入视频再返回首页时，脚本没有重新接管首页；
- 页面离开首页后遗留观察器或覆盖层。

边界要求：

- 不新增视频处理能力、倍速档位、按钮或支持页面；
- 不改变推荐批次判定、十批上限、卡片字段或原生卡片呈现；
- 不把会话历史改为持久历史或跨标签共享；
- 只有已经注入脚本的同一文档发生状态变化时才允许恢复既有能力。

### 4.4 通用输入与设置一致性

允许调查并在证实后修复：

- 快速连续缩放时并发读改写吞掉步进；
- Options 普通设置写入失败后 UI 与实际存储不一致；
- Options 打开期间收到其他上下文设置变更时 UI 不更新；
- 备份错误文本被当作 HTML 插入设置页。

边界要求：

- 不改变缩放步长、边界、快捷键或指示器视觉；
- 不新增保存中状态、成功提示或错误弹窗；
- 只在写入失败时恢复原值并记录现有控制台错误；
- 备份格式、字段白名单及导入成功行为保持不变。

### 4.5 未证实风险的处理

以下项目只有在得到稳定证据后才允许实施，否则本轮保持不变：

- 知乎隐藏虚拟列表项是否影响真实站点无限滚动；
- B站换一换是否必须允许部分 URL 重合；
- 标签协调器冷启动查询与实时事件是否会在真实 Chromium 中产生错误缓存；
- 自定义壁纸双事务是否会遗留无法回收的孤立 Blob；
- 非生产 DOM 节点是否仍需从壁纸状态控制器删除。

这些项目不得仅依靠推测改写现有算法。

## 5. 行为保持型模块拆分

### 5.1 拆分目标

优先处理当前职责最密集且已有测试入口的文件：

- `options/options.js`；
- `bili-tool/bili-tool.js`；
- `search-box/search-box.js`；
- 必要时拆出与本轮缺陷修复直接相关的通用控制器。

不以追求任意行数指标为目标。只有能够形成明确职责、减少重复或隔离生命周期的代码才允许迁移。

### 5.2 拆分约束

- 只搬迁现有实现，不重写视觉、文案、DOM 结构或算法；
- 新模块继续使用无构建 classic script/IIFE 模式，与当前仓库一致；
- 模块依赖通过显式 `create(options)` 或只读导出表达；
- HTML/Manifest 中的加载顺序必须由结构测试覆盖；
- 不新增运行时第三方依赖；
- 不借拆分重命名现有 DOM ID、CSS class、存储键或消息 action；
- 每次只拆一个职责，立即运行对应 characterization 测试；
- 若拆分无法由现有测试证明行为保持，先补测试，不继续扩大迁移范围。

### 5.3 预期职责边界

允许优先形成以下模块，最终名称可按代码证据微调：

- Options 设置表单持久化与外部同步；
- Options 知乎同步 Port 生命周期；
- Options 备份导入导出；
- B站视频工具静态 SVG/样式资产；
- Search Box 热搜数据与轮播控制。

未完成充分保护时，不强行拆分高耦合的视频 Canvas/滤镜或标签协调状态机。

## 6. 测试与质量门禁

### 6.1 必须补充的针对性测试

至少覆盖实际实施的以下场景：

- Options Port 断开后重连并继续发送同步命令；
- 知乎 session 首次持久化失败后任务可重新开始；
- 壁纸浏览记录存储异常不阻止渲染完成；
- 壁纸初始化首次失败后可再次初始化或安全降级；
- 删除最后收藏时第二阶段失败不会形成持久化分叉；
- 收藏同步两个键分批到达时使用一致快照；
- 热搜短响应不进入缓存且后续仍可刷新；
- B站工具 `false → true` 在当前文档生效；
- B站历史恢复与关闭乱序时旧响应不复活状态；
- 连续缩放事件按顺序累计；
- 普通设置写失败回滚、外部变更同步 UI；
- 拆分后生产 HTML/Manifest 包含全部新模块且顺序正确。

### 6.2 审查要求

完成后必须进行：

- 当前分支相对实施前基线的完整 diff 审查；
- 新旧公开契约、存储键、权限、内容脚本匹配范围对照；
- 所有新增 catch、重试、队列和回滚路径的终止性审查；
- 事件监听注册与释放、定时器和 Blob URL 生命周期审查；
- 生产 HTML 与发布 allowlist 的新文件一致性审查；
- VS Code 静态诊断与仓库静态校验；
- 与改动模块直接相关的定向自动化测试。

Playwright、完整 E2E 或完整测试套件只在获得本轮明确命令授权后执行；未执行项必须在交付说明中明确列出，并交由人工冒烟验收补足。
