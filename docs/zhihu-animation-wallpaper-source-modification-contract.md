## 2. FRE2 与官网知乎动画

### 2.1 统一基准

以官网当前“黑名单目标内容整块红色警示”的表达为视觉基准，但修复官网现有的下方内容重复位移问题。

FRE2 与官网允许因容器尺寸不同使用不同像素尺寸，但必须保持相同的：

1. 内容结构：普通内容 → 红色黑名单目标内容 → 折叠占位 → 后续普通内容 → 本地隐私提示；
2. 颜色语义：普通内容为中性/蓝色，目标内容整块使用一致的红色警示体系，折叠占位使用蓝色；
3. 动画顺序：扫描 → 标识黑名单目标 → 目标内容折叠消失 → 蓝色占位出现 → 临时查看反馈 → 恢复循环；
4. 时间轴：统一为 4.5 秒，关键阶段百分比一致；
5. 布局逻辑：目标内容高度变化只驱动下方内容自然补位一次，不允许绝对定位不动，也不允许自然补位后再次额外位移；
6. 占位逻辑：占位必须准确占据折叠后目标内容所在位置，与下方普通内容保持和其他卡片一致的间距，不重叠、不留异常大空白；
7. 减少动画模式和动画暂停状态下不出现错位或残留动画。

### 2.2 FRE2 必须修改

- 将目标卡片、头像、标题骨架、正文骨架和“黑名单用户”标识改成与官网相同的红色语义；
- 去掉目标头像的独立粉色内联样式，避免覆盖统一规则；
- 将下方普通卡片从绝对定位改为正常文档流，让它随目标卡片高度自然上移和恢复；
- 让目标卡片折叠高度与占位高度一致，并统一官网时间轴；
- 不改变 FRE2 演示整体尺寸和功能卡片交互。

### 2.3 官网必须修改

- 保留当前整块红色目标内容设计；
- 将占位顶部对齐目标卡片的实际起始位置；
- 删除下方普通卡片的额外位移动画，只保留目标卡片高度变化产生的自然补位；
- 清理不再使用的旧 6 秒动画和下方卡片位移动画，避免两套动画叠加；
- 不改变官网该模块文案和其他网站增强动画。

### 2.4 动画验收

- 在 FRE2 和官网分别观察至少两个完整循环；
- 初始状态下三张内容卡片间距一致；
- 目标卡片为整块红色警示，两个页面颜色语义一致；
- 折叠后占位与后续内容之间无重叠、无异常大空隙；
- 后续内容只移动一次，恢复时不跳动；
- 动画暂停、切换标签及减少动画模式下布局稳定。

## 3. NTP 锁定壁纸切换到必应每日壁纸

### 3.1 已确认根因

`pinnedDate` 是锁定壁纸的唯一条件，且在壁纸选择时优先级高于 `mode`。本地上传会自动设置 `pinnedDate`。

当前“必应每日壁纸”入口只设置：

- `mode = 'daily'`；
- `lastActiveMode = 'daily'`；

却不清除 `pinnedDate`。因此可能出现：

- 当前画面被临时强制显示为今日 Bing 壁纸，但锁定状态仍存在；
- 设置面板同时显示“必应每日”和“当前锁定单张壁纸”；
- 刷新或重新打开 NTP 后，`selectWallpaper()` 再次按 `pinnedDate` 恢复旧锁定壁纸；
- 本地上传发生在原本已经是 `daily` 模式时，“必应每日”单选项仍处于选中状态，普通 `change` 事件无法表达用户再次点击它以退出锁定。
- 本地上传壁纸会插入合并历史头部，而每日模式原先直接使用 `history[0]`；即使成功清除 `pinnedDate`，仍可能再次选中同一张本地壁纸，造成“锁定没有释放”的表象。

### 3.2 目标行为

用户明确选择“必应每日壁纸”时，含义必须是退出任何单张锁定并恢复每日自动壁纸：

1. 清除 `pinnedDate`；
2. 设置 `mode = 'daily'`；
3. 设置 `lastActiveMode = 'daily'`；
4. 退出预览状态并把浏览索引归到最新；
5. 通过正常壁纸选择逻辑显示当日 Bing 壁纸；
6. 保存设置；
7. 更新当前壁纸、锁定状态、来源选择器和状态文案；
8. 不删除锁定过的收藏或本地上传壁纸，它们仍保留在壁纸库。

### 3.3 交互要求

- 锁定状态下，“必应每日壁纸”必须仍是可操作的退出锁定入口；
- 锁定状态是高于来源模式的独立有效状态；此时“必应每日壁纸”和“我的壁纸库”都不得显示为当前已选，避免底层模式与实际生效状态冲突；
- 锁定状态卡片是此时唯一的当前状态指示；底层 `mode` 只用于解除锁定后恢复，不直接显示为已生效来源；
- 本地上传壁纸没有描述时，锁定卡片显示“本地上传壁纸”，不得暴露 `custom:时间戳` 内部标识；
- 即使底层 `mode` 原本已是 `daily`、单选项看起来已选中，再次点击“必应每日壁纸”也必须解除 `pinnedDate` 并切回每日壁纸；
- “我的壁纸库”及其播放模式在锁定状态下维持现有约束，本轮不重新设计；
- “解除锁定”按钮继续保留原行为；
- 所有现存的“切换到必应每日”代码路径应使用同一行为，不能一处清锁、一处保留锁。
- 收藏为空而自动回退每日的所有路径，必须同时将 `mode` 和 `lastActiveMode` 设为 `daily`，并选择最新 Bing 壁纸，不能直接使用可能为本地图片的 `history[0]`。

### 3.4 复现与验收矩阵

至少验证以下路径：

1. 上传本地壁纸自动锁定，随后点击“必应每日壁纸”；
2. 锁定一张 Bing 收藏壁纸，随后点击“必应每日壁纸”；
3. 在“我的壁纸库 / 每日随机”基础上锁定一张，再切换“必应每日壁纸”；
4. 本地上传前底层模式本来就是 `daily`，上传后再次点击已经显示选中的“必应每日壁纸”；
5. 切换后刷新 NTP；
6. 切换后关闭并重新打开 NTP；
7. 检查原收藏和本地上传图片仍在壁纸库。

所有路径必须满足：

- `pinnedDate` 已清空；
- 当前模式为 `daily`；
- 当前画面是正常选出的最新 Bing 壁纸，不得把历史头部的本地上传壁纸当作每日壁纸；
- 锁定状态卡片消失；
- 来源与锁定 UI 不矛盾；
- 刷新或重开后不会回到旧锁定壁纸；
- 收藏和本地图片不丢失。
